# ADR-001: Local-first desktop application

## Status
Accepted

## Context
Приложение предназначено для малого семейного бизнеса (2–3 оператора, один компьютер). Нужен минимальный порог входа: установил — работает. Нет DevOps-ресурсов для поддержки серверной инфраструктуры. Интернет может быть нестабильным.

## Decision
Строим desktop-приложение на **Tauri 2 + React + TypeScript + Vite + SQLite**.

### Почему Tauri 2
- Нативное окно на Windows без тяжёлого Electron.
- SQLite через `tauri-plugin-sql` или прямой доступ через Rust-бэкенд.
- Размер установщика ~10–15 MB vs ~150 MB у Electron.
- Tauri 2 стабилен и поддерживает Windows 10+.

### Почему SQLite
- Один файл БД — просто бэкапить (копия файла).
- Нет необходимости в отдельном сервере СУБД.
- Для объёма данных малого бизнеса производительности SQLite более чем достаточно.
- WAL mode для надёжности.

### Почему React + TypeScript
- Широкая экосистема компонентов.
- TypeScript снижает количество ошибок.
- Знакомый стек для быстрой разработки.

## Consequences
- Нет мультидевайс-синхронизации в MVP. Если понадобится — добавлять отдельным слоем поверх (e.g. cr-sqlite, Turso).
- Обновления приложения — ручная установка новой версии или Tauri updater.
- Нет веб-доступа для клиентов.

## Alternatives considered
- **Electron**: слишком тяжёлый для простого приложения.
- **Web app + local server**: лишняя сложность (нужен процесс-сервер), нет преимуществ при одном компьютере.
- **Native (C# / WPF)**: более высокий порог разработки, меньше переиспользуемых компонентов.
