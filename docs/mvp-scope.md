# MVP Scope

## In scope

### Модуль «Операционный»
- [ ] Справочник клиентов (имя, телефон, pricing program)
- [ ] Справочник pricing programs и pricing rules
- [ ] Справочники материалов: форматы, материалы блока/обложки, ламинация, отделка
- [ ] Создание / редактирование заказа с позициями (book, print, service, extra)
- [ ] Автоматический расчёт цены по pricing rules
- [ ] Сохранение snapshot параметров и price breakdown в позиции заказа
- [ ] Три независимых статуса заказа: production, payment, delivery
- [ ] Частичная оплата (несколько платежей на один заказ)
- [ ] Выдача заказа (в т.ч. до полной оплаты)
- [ ] Печать квитанции для клиента
- [ ] Печать производственного листа / наряда
- [ ] Список заказов с фильтрацией и поиском

### Модуль «Финансовый»
- [ ] Company accounts: cash, card, bank
- [ ] Журнал finance transactions (полный список типов — см. domain-finance.md)
- [ ] Автоматическое создание finance transaction при оплате заказа
- [ ] Учёт долгов поставщикам (liabilities)
- [ ] Partner settlement entries (contribution, reimbursement, profit_accrual, profit_payout, draw, adjustment)
- [ ] Прибыль по cash basis, деление 50/50
- [ ] Сводка по счетам, долгам, партнёрским балансам

## Out of scope (MVP)

- Складской учёт (остатки бумаги, чернил и т.д.)
- Личный кабинет клиента
- Онлайн-оплата
- Синхронизация / мультидевайс
- Аналитика и отчёты (кроме базовых сводок)
- Интеграция с внешними сервисами (банк, мессенджеры)
- Многоязычность (UI на русском)
- Аудит-лог действий пользователей (в MVP один логин без авторизации)

## Assumptions

1. Один инстанс приложения на одном компьютере — конкурентный доступ к БД не требуется.
2. Все операторы доверены — разделение прав доступа не нужно в MVP.
3. Партнёров ровно двое, доля прибыли фиксирована 50/50.
4. Валюта одна (рубли), мультивалютность не нужна.
5. Прайс-листы меняются редко; при изменении прайса старые заказы не пересчитываются (snapshot).
6. Backup — ответственность пользователя (копия файла БД).
